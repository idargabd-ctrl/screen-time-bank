Разведка и приведение сервера в рабочее состояние. Ничего не программируем:
задача в том, чтобы к началу Этапа 1 была машина, до которой можно достучаться
и на которой есть Docker.

## Сеть

- [x] **Ethernet мёртв.** `NO-CARRIER` сохраняется при поднятом интерфейсе,
      исправном кабеле, проверенном порте роутера и включённом адаптере.
      Для машины 2010 года обычное дело. Разъём больше не трогаем.
- [x] **Wi-Fi работает.** Карта видит сети, диапазон 2,4 ГГц.
- [x] **Настроен через `server/setup-wifi.sh`** — `wpa_supplicant` для
      подключения, `systemd-networkd` для адреса.

Почему именно так: в системе **нет ни одного DHCP-клиента** и нет
NetworkManager, а поставить их без сети невозможно. У `systemd-networkd`
DHCP-клиент встроенный, и сам он входит в systemd — поэтому обошлись без
загрузок.

- [x] **Переживает перезагрузку** — проверено: после `reboot` машина сама
      поднимает Wi-Fi и SSH, вмешательства не требуется.
- [ ] **Домашняя сеть ещё не прописана.** Настройка делалась в офисе, поэтому
      в конфиге сейчас только хотспот телефона. См. раздел «Дома» ниже.

Корпоративную сеть работодателя намеренно не настраивали: почти наверняка
WPA2-Enterprise, а это означало бы рабочие учётные данные в файле на домашней
машине, которая проработает годы.

## Доступ

- [x] `openssh-server` и `avahi-daemon` установлены
- [x] Вход по ключу без пароля: `ssh agent` с рабочего ноутбука
- [x] Имя `agent.local` разрешается — адрес запоминать не нужно

Ключ и алиас настроены на рабочем ноутбуке: `~/.ssh/id_ed25519_childmind`
и запись `Host agent` в `~/.ssh/config`.

### Ловушка: VPN режет локальную сеть

Пока на рабочем ноутбуке включён туннель **AmneziaWG**, сервер недоступен
полностью: не проходит ни ping, ни порт 22, машина не появляется даже в
ARP-таблице. Маршрутизация при этом выглядит правильной — блокировка происходит
уровнем ниже, фильтрами Windows.

**Перед работой с сервером туннель выключать.** Симптом «сервер не отвечает»
выглядит одинаково независимо от причины, и через месяц это забудется.

## Осталось сделать

### Дома: домашний Wi-Fi

Проще всего с консоли самого ноутбука — команда короткая, набрать несложно:

```bash
sudo bash ~/child-mind/server/setup-wifi.sh
```

На первый вопрос — **настоящую домашнюю сеть**, на второй — хотспот телефона.
Хотспот вводить обязательно: если в домашнем пароле окажется опечатка, он
останется единственным способом попасть на машину.

- [ ] Домашняя сеть прописана
- [ ] После перезагрузки поднимается сама
- [ ] `ssh agent` работает с рабочего ноутбука по домашней сети

### Docker — сделано

Скачали в офисе: хотспот телефона раздавал не мобильный интернет, а Wi-Fi,
поэтому объём значения не имел.

- [x] Docker 29.8.0, Compose v5.5.1 — из официального репозитория Docker
- [x] `docker ps` работает без `sudo`, пользователь в группе `docker`
- [x] Служба активна, автозапуск включён (systemd, вход в систему не требуется)
- [x] Образы скачаны: **6,1 ГБ**, а не 2 ГБ, как я оценивал — Home Assistant
      3,43 ГБ и familylink-auth 2,66 ГБ (внутри полноценный Chromium).
      На диске занято 7,5 ГБ из 232
- [x] Контейнеры подняты, порты привязаны к `127.0.0.1`
- [x] Потребление в покое: около 1,1 ГБ из 5,7 — опасения про нехватку памяти
      не подтвердились

В Debian trixie пакета с compose v2 нет вообще, только устаревший
`docker-compose` на Python, не понимающий ключ `name:` в нашем
`docker-compose.yml`. Отсюда официальный репозиторий, а не Debian.
