# Домен и доступ к сайту с планшета

Сайт открывается на планшете по адресу **`http://uroki.example.ru`** — но
только из домашней сети. В интернет он не выставлен, и это осознанный выбор.

## Почему так

Планшет живёт дома, и минуты выдаются на планшет. Значит, сайту достаточно
быть видимым в домашней сети — а для этого не нужны ни VPS, ни туннель, ни
HTTPS-сертификат. Стоимость решения: 0 ₽ сверх домена.

Домен при этом всё же используется. Запись `uroki.example.ru` в DNS
указывает не на сервер в интернете, а на **адрес ноутбука в домашней сети**
(вида `192.168.x.x`). Это законно и работает: DNS не проверяет, куда ведёт
запись. Снаружи дома такой адрес просто никуда не ведёт.

```
планшет (домашний Wi-Fi) ──▶ http://uroki.example.ru ──▶ 192.168.x.x:80 ──▶ ноутбук
```

Что теряем: сайт не работает вне дома — у бабушки, в поездке, через хотспот.
Когда это понадобится, добавляется VPS-«дверь»: скрипты для неё готовы,
описание в конце файла. Адрес сайта при этом не меняется.

Cloudflare Tunnel из первоначального плана отклонён: с 2025 года трафик к
Cloudflare в России замедляют. VPS отложен из-за цены (от 600 ₽/мес с
публичным адресом у Timeweb).

---

## Шаг 1. Домашний Wi-Fi на сервере

Дома, за ноутбуком-сервером (у него нет графики, нужны клавиатура и экран):

```bash
sudo bash ~/child-mind/server/setup-wifi.sh
```

Скрипт спросит название и пароль домашней сети, затем хотспот как запасную.
Пароли вводите сами. В конце он печатает адрес вида `192.168.1.50/24` —
запишите часть до `/`: это и есть адрес сервера, дальше он обозначен
`СЕРВЕР_IP`.

После этого с рабочего ноутбука в той же сети `ssh agent` должен работать
как раньше (AmneziaWG выключен).

---

## Шаг 2. Закрепить адрес в роутере

Роутер раздаёт адреса сам и в принципе может выдать ноутбуку другой. Чтобы
`СЕРВЕР_IP` не менялся, в настройках роутера найдите список подключённых
устройств, ноутбук (имя `agent`) и пункт вроде «Закрепить IP» / «Статический
DHCP» / «Резервирование адреса». Закрепите текущий адрес.

Если такого пункта нет — не страшно: роутеры и так помнят устройство по
MAC-адресу и обычно выдают тот же адрес неделями. Признак, что адрес
поменялся: сайт перестал открываться, а `ssh agent` — работать. Тогда
`ip -4 -br addr` на сервере покажет новый адрес, и его нужно поправить в
шаге 3.

---

## Шаг 3. Направить домен на сервер

Там, где управляется DNS-зона домена (панель reg.ru → домен → «DNS-серверы и
управление зоной», либо Яндекс, если зона делегирована туда), добавьте
одну запись:

| Тип | Имя (поддомен) | Значение | TTL |
| --- | --- | --- | --- |
| A | `uroki` | `СЕРВЕР_IP` | по умолчанию |

Запись разойдётся за несколько минут, иногда до часа. Проверить с рабочего
ноутбука:

```bash
nslookup uroki.example.ru
```

Должен вернуться `СЕРВЕР_IP`.

---

## Шаг 4. Выложить сайт на порт 80

С рабочего ноутбука, из папки проекта:

```bash
python tools/deploy.py
```

Сайт теперь слушает порт 80 — стандартный для `http://`, поэтому адрес без
двоеточия и цифр. Ролики закрыты за кодом входа, код входа защищён от
перебора: в домашней сети это перестраховка, но она ничего не стоит.

Проверка с рабочего ноутбука в браузере: `http://uroki.example.ru` — должна
открыться страница ввода кода.

---

## Шаг 5. Сменить код входа

Временный код `1234` заменить. На домашнем сервере:

```bash
cd ~/child-mind && python3 tools/set_pin.py
```

Шесть цифр — хорошо. Код вводится на планшете один раз: кука живёт 90 дней.

---

## Шаг 6. Family Link: разрешить сайт

В приложении Family Link → Профиль-1 → **Контроль контента → Google Chrome →
Управление сайтами → Одобренные**: добавьте `uroki.example.ru` и удалите
заглушку `ru.wikipedia.org`.

Режим Chrome «только одобренные сайты» уже включён на этапе 1, и Chrome
стоит в безлимите — учиться можно и при исчерпанной квоте.

На планшете откройте `http://uroki.example.ru` в Chrome, введите новый код,
проверьте, что ролик в разборе ВПР играет и перематывается. Chrome покажет
«Не защищено» у адреса — это про отсутствие HTTPS, в домашней сети это
нормально.

## Если не открылось

| Что видно | Причина | Что делать |
| --- | --- | --- |
| С рабочего ноутбука открывается, с планшета нет | Планшет не в домашнем Wi-Fi или Family Link ещё не пустил | Проверить сеть на планшете; подождать минуту после правки одобренных сайтов |
| `nslookup` показывает верный адрес, сайт не открывается ни с чего | Роутер блокирует DNS-ответы с локальными адресами (защита от DNS rebinding — редко, но бывает) | В роутере отключить эту защиту, либо вписать в одобренные сайты сам `СЕРВЕР_IP` и открывать `http://СЕРВЕР_IP` |
| `nslookup` показывает не тот адрес | DNS ещё не разошёлся или запись с опечаткой | Подождать, перепроверить шаг 3 |
| По `http://СЕРВЕР_IP/` открывается, по имени — нет, при этом с другого устройства имя работает | Устройство держит в кэше старый ответ «домена нет» — он остаётся с того момента, когда запись ещё не разошлась (так было с телефоном 12.09) | Включить и выключить авиарежим (или переподключить Wi-Fi) — кэш имён сбрасывается. Если не помогло: Настройки → Частный DNS → «Выкл.», чтобы устройство спрашивало роутер |
| Раньше работало, перестало вместе с `ssh agent` | Роутер выдал ноутбуку другой адрес | Шаг 2, затем поправить запись в шаге 3 |

## Позже: доступ извне через VPS

Когда понадобится сайт вне дома, добавляется маленький VPS-«дверь»:
Caddy на нём принимает `https://uroki.example.ru`, а домашний сервер сам
держит к нему обратный SSH-туннель. На VPS ничего секретного нет.

Скрипты готовы: `server/setup-tunnel.sh` (домашний сервер, создаёт ключ и
службу `uroki-tunnel`) и `server/vps-setup.sh` (VPS: Caddy, пользователь
туннеля, файрвол). Порядок:

1. Заказать VPS в России с **публичным IPv4** (Beget, VDSina, Timeweb — от
   ~300 ₽/мес; бэкапы не нужны), Debian или Ubuntu, добавить ключ
   `C:\Users\<user>\.ssh\id_ed25519_childmind.pub`.
2. На домашнем сервере: `sudo bash ~/child-mind/server/setup-tunnel.sh VPS_IP`
   — напечатает публичный ключ туннеля.
3. На VPS: `bash vps-setup.sh uroki.example.ru "ssh-ed25519 …ключ из п.2…"`
   (скрипт перенести через `scp server/vps-setup.sh root@VPS_IP:/root/`).
4. A-запись `uroki` перевести с `СЕРВЕР_IP` на `VPS_IP`. Планшет продолжит
   ходить по тому же адресу, но уже через VPS и по HTTPS — и дома, и вне.

В Family Link менять ничего не придётся: адрес тот же.
